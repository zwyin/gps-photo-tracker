# GPS Photo Tracker 日志系统设计

## 需求

1. **分级日志**：access log（处理记录概要）+ debug log（匹配细节）
2. **滚动删除**：30 天 + 最大 50MB 双重约束
3. **日志可视化**：GUI 调试窗口，用户自助排查
4. **不造轮子**：用成熟组件

## 方案选型

| 方案 | 优点 | 缺点 |
|------|------|------|
| `concurrent-log-handler` | 双约束一步到位 | 新增依赖，多进程安全对本项目无用 |
| **stdlib `TimedRotatingFileHandler`** | 零依赖，内置按天轮转 | 需自行补充总量检查（~10 行代码） |

**决策：用 stdlib**。本项目是单进程桌面应用，不需要多进程安全。`TimedRotatingFileHandler` 按天轮转 + `backupCount=30` 保留 30 天，总量检查用一个 `cleanup_by_total_size` 方法补充。

## 日志文件结构

```
logs/
├── operations.log      # 操作记录（启动/完成/参数）
├── operations.log.1    # 轮转备份
├── matches.log         # 匹配结果记录
├── writes.log          # EXIF 写入记录
├── debug.log           # 详细调试日志（核心匹配细节）
└── errors.log          # 错误集中记录
```

## 日志分级

| 文件 | 级别 | 内容 | 示例 |
|------|------|------|------|
| operations.log | INFO | 用户操作、参数、统计 | `START | mode=preview, photos=120` |
| matches.log | INFO | 每张照片匹配结果 | `OK DSC_001.jpg | interpolated | GPS(25.03,121.52)` |
| writes.log | INFO/WARNING | EXIF 写入/覆盖 | `WRITE DSC_001.jpg -> GPS(25.03,121.52)` |
| debug.log | DEBUG | 匹配算法细节、轨迹点搜索 | `Searching segments for t=1700000, found 3 candidates` |
| errors.log | ERROR | 异常和错误 | `GPX parse error: Invalid XML` |

## 滚动删除策略

```python
# 时间约束：TimedRotatingFileHandler(when="D", interval=1, backupCount=30)
# → 自动保留最近 30 天，更早的 .log.N 文件自动删除

# 空间约束：cleanup_by_total_size(max_total_mb=50)
# → 遍历 log_dir 所有 .log* 文件，总和超限时从最旧的开始删
```

## GUI 日志查看器

在主窗口添加"调试"菜单/按钮，打开 LogViewerDialog：

- **QPlainTextEdit** 显示日志内容（限制最大行数 5000）
- **级别筛选**：ComboBox 选择查看哪个日志文件
- **搜索框**：QLineEdit 实时过滤
- **自动滚动**：新日志到达时自动滚到底部
- **清除/导出**：按钮
