## BUG-1：Review 应用后 GPS 列高亮不一致

**原始反馈**：Review 对话框选择"应用所有建议"后，GPS前有颜色标注，GPS后没有颜色标注。

**改动内容**：

- `_apply_review_to_table` 中，更新 GPS(后) 后新增颜色高亮逻辑：
  - GPS(后) 与 GPS(前) 相同 → 浅绿色 `#dcf5dc`
  - GPS(后) 与 计算GPS 相同 → 浅绿色 `#dcf5dc`
  - GPS(后) 为新赋值（跟随/手动） → 浅蓝色 `#c8e6ff`
- `_quick_follow_gps`（左右键跟随）同样添加了颜色高亮（绿色=与GPS前相同，蓝色=新跟随）

**涉及文件**：`main_window.py`

**验证方法**：处理完成后点 Review → 应用建议 → 回到结果列表，观察 GPS(后) 列是否有颜色标注。选中失败行按 ← → 键跟随，同样观察颜色。

## BUG-2：分栏分隔线无视觉指示

**原始反馈**：左右分界线、上下分界线均无可视元素，用户无法发现可拖动。

**改动内容**：

- 主水平 splitter（左右面板之间）和右侧垂直 splitter（结果列表与预览之间）均设置：
  - `setHandleWidth(4)` — 4 像素宽度
  - 灰色背景 `#c0c0c0`
  - hover 时变蓝 `#4a9eff`

**涉及文件**：`main_window.py`

**验证方法**：启动应用后观察左右面板之间、结果列表和图片预览之间的分隔线。鼠标悬停时应变为蓝色，拖动可调整面板大小。

## BUG-3：拖动分隔线时预览图尺寸未动态跟随

**原始反馈**：结果列表与图片预览区域之间的分隔线可拖动，但预览图大小不变。

**改动内容**：

- `PhotoPreview` 移除 `setFixedSize(200, 200)`，改为 `setMinimumSize(80, 80)`
- 新增 `_full_pixmap` 保存原始尺寸图片
- 新增 `resizeEvent` + `_rescale` 方法，窗口大小变化时重新缩放
- `_load_thumbnail` 保存原图到 `_full_pixmap`，缩略图缓存仍为 200x200
- `show_photo` 缓存命中时重新加载原图并调用 `_rescale`
- 修复缓存命中时磁盘文件消失导致 `_full_pixmap` 残留上一张照片的问题

**涉及文件**：`photo_preview.py`、`test_gui.py`（更新两个测试类从断言 200x200 改为断言 minimumSize ≥ 80）

**验证方法**：处理照片后选中一张查看预览，拖动结果列表和预览之间的分隔线，预览图应实时跟随缩放。

- 所有 `setItem` / `item()` 调用的列索引全部更新（GPS前 1→2, 计算GPS 2→3, GPS后 3→4, 方式 4→5, 状态 5→6）

**涉及文件**：`result_table.py`（表头定义）、`main_window.py`（所有列引用）

**验证方法**：处理照片后观察结果列表，"文件名"列右侧应显示拍摄日期时间（如 `2024-03-15 14:30:22`）。

## BUG-4：孤立照片匹配缺陷 + match_tail 重命名

**原始反馈**：头部/尾部孤立照片被不公平排除，无法进入孤立匹配分支。`match_tail` 参数名误导。

**改动内容**：

- 重命名：`match_tail` → `match_isolated`，`TAIL_ISOLATED` → `ISOLATED_DISABLED`
- `_find_segment` 改为两级匹配：先精确（段内），再容差（段外但在 `isolated_window` 内）
- 头部/尾部/中间孤立三种场景统一处理
- 设置对话框和配置面板保留 `match_tail` 向后兼容

**涉及文件**：`gps_matcher.py`、`models.py`、`main_window.py`、`settings_dialog.py`、`config_panel.py`

**验证方法**：处理含头部/尾部照片的场景，验证孤立匹配是否生效。禁用"匹配孤立照片"后确认这三种场景都返回 ISOLATED_DISABLED。

## BUG-5：已有 GPS 照片未跳过匹配

**原始反馈**：参数"覆盖已有GPS"未勾选时，已有 GPS 的照片仍走匹配流程，匹配失败时被标记为失败。

**改动内容**：

- `MatcherConfig` 新增 `overwrite_gps: bool = False`
- `GPSMatcher.match()` 入口过滤：`overwrite_gps=False` 时跳过 `has_gps=True` 的照片
- 跳过照片返回 `MatchResult(success=True, method="skipped", gps=photo.existing_gps)`
- GUI 显示"已跳过"状态，方式列浅灰色 `#e6e6e6` 背景
- 统计中不计入失败数，归入"跳过(已有)"分类
- `worker.py` 修正 `overwritten` 标志，排除 `method="skipped"` 的照片
- 新增 5 个单元测试覆盖跳过逻辑

**涉及文件**：`gps_matcher.py`、`models.py`、`worker.py`、`main_window.py`

**验证方法**：选择含已有 GPS 照片的目录，确保"覆盖已有GPS"未勾选。处理后观察这些照片显示"已跳过"而非"失败"。

## BUG-6：Review 修正后成功率统计未更新

**原始反馈**：匹配失败照片经 Review 修正后，成功率统计仍按原始失败状态计算。

**改动内容**：

- `_update_stats_card` 区分初始匹配和 Review 修正：
  - 初始方法：插值、就近、已跳过
  - Review 方法：跟随上一个/下一个、手动GPS、手动坐标
- 当存在 Review 修正时，显示双阶段成功率：`成功率: 64/65 (98.5%) → 65/65 (100%)`
- 无 Review 修正时只显示单一成功率

**涉及文件**：`main_window.py`

**验证方法**：处理后 Review 修正失败照片，观察统计行是否显示初始→最终的成功率变化。

## FEAT-3：方式列按匹配类型用不同浅色区分

**原始反馈**：需要直观区分不同匹配方式。

**改动内容**：

- `_METHOD_COLORS` 类常量集中管理颜色映射：
  - 就近 = 浅绿 `#dcf5dc`
  - 插值 = 浅蓝 `#dbeaff`
  - 跟随上一个 = 浅红 `#ffdcdc`

  - 手动GPS/手动坐标 = 浅紫 `#e6dcff`
  - 已跳过 = 浅灰 `#e6e6e6`
- 所有更新方式列的位置统一使用 `_METHOD_COLORS`（初始处理、Review 应用、箭头键跟随）

**涉及文件**：`main_window.py`

**验证方法**：处理后观察方式列颜色区分，Review 修正和箭头键跟随后同样应有对应颜色。
