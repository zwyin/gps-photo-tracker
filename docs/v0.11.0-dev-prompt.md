# v0.11.0 开发启动提示词

将以下内容粘贴到新会话中启动开发：

---

## 提示词

```
按 v0.11.0 迭代计划开始开发。先阅读以下文档：
- docs/v0.11.0-iteration-plan.md（需求和 bug 清单，6 bug + 4 feature）
- docs/execution-flow-v0.11.0.md（完整执行流程，含 GPS 匹配算法详细分析）

本次共 10 项，按依赖关系分 5 批执行。

## 第一批：核心匹配逻辑（BUG-4 + BUG-5）

这两个都改 gps_matcher.py，必须一起做，一起测试。

### BUG-4：孤立照片匹配缺陷 + match_tail 重命名
- _find_segment 改为两级匹配：先精确（段内），再容差（段外但在 isolated_window 内）
- 容差匹配的照片自然被 Step 2 判定为孤立，进入 match_isolated 分支，逻辑统一
- 重命名：match_tail → match_isolated，TAIL_ISOLATED → ISOLATED_DISABLED
- 全量替换引用，包括 GUI 控件标签
- 单元测试覆盖头部/尾部/中间孤立三种场景

### BUG-5：已有 GPS 照片未跳过匹配
- overwrite_gps=False 时，has_gps=True 的照片在匹配入口直接跳过
- 跳过的照片返回 method="skipped"，状态显示"已跳过"
- 不计入失败数

完成后：跑完整测试套件 + 端到端验证（PREVIEW 模式，含头部/尾部照片和已有 GPS 照片）

## 第二批：结果列表颜色（BUG-1 + FEAT-3）

都在 result_table.py，可并行。

### BUG-1：GPS 前后列高亮不一致
- Review 应用后，跟随上/下条目的 GPS 前有颜色、GPS 后没颜色
- GPS 前后应有对称高亮

### FEAT-3：方式列按类型浅色区分
- 就近=浅绿，差值=浅蓝，跟随上一个=浅红，跟随下一个=浅黄

完成后：跑测试 + 启动 GUI 验证颜色效果

## 第三批：总览统计（FEAT-2 + FEAT-4 + BUG-6）

三个紧密关联，一起做。

### FEAT-2：处理前总览行
- 列表上方新增处理前统计：总数、有GPS数、GPS比例百分比

### FEAT-4：总览行样式统一
- 处理前/处理后两行：字体大小、颜色、字段顺序完全统一
- 新增成功率提升差值：GPS覆盖率: 45.0% → 78.3% (+33.3%)

### BUG-6：Review 修正后成功率未更新
- 总览需展示两个成功率：
  - 成功率-初始：程序自动匹配（如 64/65 = 98.5%）
  - 成功率-最终：人工干预后（如 65/65 = 100%）
- Review 修正的照片不再计入失败

完成后：跑测试 + 启动 GUI 验证总览显示

## 第四批：结果列表增强（FEAT-1）

### FEAT-1：新增日期时间列
- 数据来源：照片 EXIF 拍摄时间
- 位置：文件名列之后
- 注意列宽分配

完成后：跑测试 + GUI 验证

## 第五批：UI 完善（BUG-2 + BUG-3）

### BUG-2：分隔线无视觉指示
- 左右、上下分隔线加可见视觉提示（手柄/粗线/hover光标）

### BUG-3：预览图尺寸逻辑
- 图片宽度：预览区宽度的 30%，随窗口动态变动
- 图片高度：占满预览区高度，随窗口动态变动

完成后：必须启动 GUI 手动验证拖动效果

## 质量要求

- 每批完成后跑完整测试套件
- 第一批完成后必须端到端验证
- 所有 GUI 改动需启动应用手动确认
- 全部完成后跑覆盖率统计
- 提交前检查：execution-flow-v0.11.0.md 中的参数名和流程图与代码一致
```
