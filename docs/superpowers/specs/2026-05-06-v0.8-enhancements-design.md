# GPS Photo Tracker v0.8.0 — Enhancement Features Design

**Date:** 2026-05-06
**Scope:** EF-03, EF-04, EF-05, EF-08, EF-09, EF-10

---

## Overview

Add 6 enhancement features to the existing 4-layer architecture (GUI → Service → Core → IO). Each feature is a new core module, integrated through the service layer. No architectural changes—extend, don't restructure.

## Architecture

```
core/
  concurrency.py     ← EF-03 concurrent processing
  checkpoint.py      ← EF-04 resume after interruption
  param_tuner.py     ← EF-05 smart parameter recommendation
  track_parser.py    ← EF-08 unified track file parser
  kml_parser.py      ← EF-08 KML format parser
  tcx_parser.py      ← EF-08 TCX format parser
  report_builder.py  ← EF-09 HTML report generation
  orientation.py     ← EF-10 EXIF orientation for thumbnails
```

## EF-03: Concurrent Processing

**Goal:** ≥500 photos/min (currently ~305). Experimental feature, default single-threaded.

### Module: `core/concurrency.py`

```python
class BatchProcessor:
    def __init__(self, workers: int = 1):
        # workers=1 → sequential (default, safe)
        # workers>1 → experimental parallel mode

    def submit_all(
        self,
        tasks: list[WriteTask],
        on_progress: Callable | None = None,
        on_result: Callable | None = None,
        cancel: CancellationToken | None = None,
    ) -> list[WriteResult]:
```

- `WriteTask` / `WriteResult` are simple dataclasses in this module
- Only the **write+copy phase** is parallelized; matching stays sequential (GPSMatcher depends on neighbor context)
- Uses `concurrent.futures.ProcessPoolExecutor`
- Top-level `process_single(task)` function for subprocess safety (must be picklable)
- CancellationToken propagated via `multiprocessing.Event`
- Logging collected back to main thread (no multi-process log races)

### Integration

- `TaggingService._run_pipeline`: loop → `BatchProcessor.submit_all()`
- `ProcessOptions.workers: int = 1` (new field)
- GUI: settings adds "concurrent workers" spinner with "(Experimental)" label
- `BatchResult.concurrent_workers: int` (new field)

## EF-04: Resume After Interruption

**Goal:** Resume interrupted batch processing without restarting. Only active in COPY mode.

### Module: `core/checkpoint.py`

```python
class CheckpointManager:
    @staticmethod
    def load(output_dir: Path) -> set[str]: ...        # completed filenames
    @staticmethod
    def mark(output_dir: Path, filename: str): ...      # append record
    @staticmethod
    def complete(output_dir: Path): ...                 # delete checkpoint
    @staticmethod
    def is_interrupted(output_dir: Path) -> bool: ...
```

### Checkpoint file format (`.checkpoint.json` in output_dir)

```json
{
  "version": 1,
  "started_at": "2026-05-06T14:30:00",
  "total_photos": 1832,
  "completed": ["photo1.jpg", "photo2.jpg"]
}
```

### Integration

- `TaggingService._run_pipeline`: if `resume=True` and checkpoint exists, load completed set and skip
- After each successful write: `CheckpointManager.mark()`
- After all complete: `CheckpointManager.complete()`
- `ProcessOptions.resume: bool = False` (new field)

### Constraints

- COPY mode only (has output_dir for checkpoint location)
- PREVIEW mode: no checkpoint (no writes)
- OVERWRITE mode: no checkpoint (already modified files, unsafe to resume)

## EF-05: Smart Parameter Recommendation

**Goal:** Auto-recommend MatcherConfig based on GPX density and photo distribution.

### Module: `core/param_tuner.py`

```python
class ParamTuner:
    @staticmethod
    def recommend(segments: list[GPXSegment], photos: list[PhotoInfo]) -> MatcherConfig:
```

### Recommendation rules

1. **GPX density**: average seconds between trackpoints
2. **Photo distribution**: P25/P50/P75 of photo shooting intervals
3. **Derived parameters**:
   - `isolated_window = max(300, gpx_avg_gap * 3)`
   - `middle_time_window = max(3600, gpx_avg_gap * 10)`
   - `context_window = max(300, gpx_avg_gap * 2)`
   - `max_gps_distance`: estimate from GPS speed median (walking ~200m, driving ~500m)
   - `time_offset`: never auto-recommend (too user-specific)
   - `match_tail`: keep default True

### Constraints

- Pure computation, no IO, no external dependencies
- All recommended values within BF-01 parameter ranges
- Fallback to defaults if samples insufficient (< 5 photos or 0 segments)

### Integration

- `TaggingService.auto_tune(segments, photos) → MatcherConfig`
- GUI: ConfigPanel adds "Smart Recommend" button

## EF-08: Multi GPS Format (KML + TCX)

**Goal:** Support KML (Google Earth) and TCX (Garmin) track files alongside GPX.

### Modules

**`core/kml_parser.py`**

```python
class KMLParser:
    def parse_file(self, path: Path) -> list[GPXSegment]:
```

Parses `<Placemark><gx:Track>` and `<LineString><coordinates>` formats. Uses `xml.etree.ElementTree`.

**`core/tcx_parser.py`**

```python
class TCXParser:
    def parse_file(self, path: Path) -> list[GPXSegment]:
```

Parses `<Activity><Lap><Track><Trackpoint>`. Uses `xml.etree.ElementTree`.

**`core/track_parser.py`** — unified entry point

```python
class TrackParser:
    def parse_file(self, path: Path) -> list[GPXSegment]:
        # Dispatch by extension: .gpx → GPXParser, .kml → KMLParser, .tcx → TCXParser

    def parse_directory(self, dir: Path) -> list[GPXSegment]:
        # Scan for .gpx/.kml/.tcx files
```

### Key design

- Output type is `list[GPXSegment]` — reuses existing `TrackPoint`/`GPXSegment` data structures
- Downstream `GPSMatcher` is completely unaware of format changes
- Missing altitude → `0.0` (consistent with GPXParser behavior)
- No new dependencies — both KML and TCX are XML, parsed with stdlib

### Integration

- `TaggingService.__init__`: `GPXParser` → `TrackParser`
- `FileProvider.list_gpx` → `list_tracks`: scan `.gpx/.kml/.tcx`
- GUI file dialogs: filter adds KML/TCX

## EF-09: Export HTML Report

**Goal:** Generate self-contained HTML report with inline SVG charts after processing.

### Module: `core/report_builder.py`

```python
class ReportBuilder:
    @staticmethod
    def build(
        result: BatchResult,
        config: MatcherConfig,
        segments: list[GPXSegment],
        output_path: Path,
    ) -> Path:

    @staticmethod
    def _stats_html(result) -> str: ...
    @staticmethod
    def _pie_chart_svg(result) -> str: ...      # success/fail/skip distribution
    @staticmethod
    def _bar_chart_svg(result) -> str: ...      # reject reason distribution
    @staticmethod
    def _table_html(result) -> str: ...         # match detail table
    @staticmethod
    def _reject_analysis(result) -> str: ...    # failure analysis
```

### Report content

1. **Header**: task parameters (mode, time windows, photo count, segment count)
2. **Stats cards**: total/matched/failed/skipped/success rate
3. **SVG pie chart**: matched/failed/skipped distribution
4. **SVG bar chart**: reject reason breakdown
5. **Detail table**: filename, status, GPS coords, match method (interpolation/nearest), time delta
6. **Failure analysis**: grouped by reject reason

### Constraints

- Pure string concatenation for HTML — no Jinja2 or template engine
- SVG via math (arc calculation) + inline SVG tags
- CSS inlined — zero external dependencies, single file, offline-viewable
- UTF-8 encoding throughout

### Integration

- `ProcessOptions.generate_report: bool = False` (new field)
- `TaggingService._run_pipeline`: call `ReportBuilder.build()` at end if flag set
- Report saved to `output_dir / "report.html"` (COPY mode) or user-specified path
- GUI: completion dialog asks "Generate report?", or settings default

## EF-10: Image Orientation (Thumbnail Display Only)

**Goal:** Read EXIF Orientation tag, apply rotation when displaying thumbnails. Never modify original files.

### Module: `core/orientation.py`

```python
class OrientationReader:
    @staticmethod
    def get_orientation(path: Path) -> int | None:
        # Returns EXIF Orientation value 1-8, or None if not found

    @staticmethod
    def apply_orientation(qpixmap: QPixmap, orientation: int) -> QPixmap:
        # Apply QTransform based on orientation value

    @staticmethod
    def transform_matrix(orientation: int) -> QTransform:
        # Map orientation 1-8 to QTransform
```

### EXIF Orientation mapping

| Value | Transform |
|-------|-----------|
| 1 | None |
| 2 | Horizontal flip |
| 3 | Rotate 180° |
| 4 | Vertical flip |
| 5 | Horizontal flip + CW 90° |
| 6 | CW 90° |
| 7 | Horizontal flip + CCW 90° |
| 8 | CCW 90° |

### Integration

- `PhotoInfo.orientation: int | None = None` (new field)
- `TaggingService.scan_photos`: read orientation during scan
- GUI thumbnail loading (photo_browser_dialog, detail_dialog, photo_preview): apply orientation after loading QPixmap
- Report: include orientation value in detail table
- **Original files are never modified**

### Coverage gates

- New modules: ≥ 85%
- Service layer (after integration): ≥ 80%

- Coverage must not decrease after integration

### Test approach

- Concurrency: mock ProcessPoolExecutor, verify dispatch logic (no real multi-process tests)
- Checkpoint: use tmp_path, verify JSON read/write/complete lifecycle
- KML/TCX: test with minimal XML strings (embedded in test), verify TrackPoint extraction
- Report: verify HTML structure with string assertions, check SVG contains expected data
- Orientation: test each transform value, verify QTransform correctness
- Service integration: test new integration paths in `test_service.py`
