## 今日完成

### v0.21.0 Release — 修复 Windows 启动崩溃

- 起因：Windows 主机运行 v0.10.0 安装包报错 `Missing dependencies: Pillow>=10.0.0`，启动即崩溃。
- **根因**：`Pillow` 被声明为运行时依赖并在 `__main__.py` 启动检查、`.spec` hiddenimports 中引用，但生产代码 `src/` 从未导入它（缩略图用 PySide6 `QPixmap`，EXIF 用独立的 `piexif`）。macOS 构建走 `.spec` 会带上 Pillow；Windows/Linux 构建绕过 `.spec`（直接 `pyinstaller --onefile __main__.py`），PyInstaller 丢弃这个未被导入的库，启动检查 `__import__("PIL")` 失败 → 崩溃。
- **修复**：把 Pillow 从运行时依赖移到 `dev` 测试依赖（测试用 `PIL.Image` 造 JPEG fixture，生产不需要）。新增 2 个回归测试守卫。
  - 首次 CI 失败（误删 Pillow 导致测试收集报错）→ 读日志定位 → 改为移到 dev extra → CI 全绿。
- CI 全绿：三平台测试 + 四平台构建（macOS / Windows / Windows-debug / Linux）。

## 经验沉淀

- **依赖声明要与实际导入一致**：未被导入的依赖会被 PyInstaller 在 Win/Linux 上静默丢弃；`.spec` 的 hiddenimports 只保护 macOS。
- **CI 只在 PR 目标为 master 时触发**：目标 develop 的 PR 无 CI；改 PR base 只触发 `edited` 事件（不在默认 trigger 内），需 close/reopen 或推新 commit 才能重新触发。
- **测试 fixture 也是依赖**：删依赖前要 grep `tests/`，不只看 `src/`。
