# GPS Photo Tracker - Bug 历史与避坑指南

**版本：** v1.0
**日期：** 2026-05-05
**来源：** gps-photo-tracker v1.0 ~ v7.2.0 全部 git 提交梳理

> 重写时必读。按功能模块分类，记录每个 bug 的根因和防范措施。

---

## 1. GPS 匹配算法

### Bug-ALG-01：时间窗口参数被硬编码，不生效

- **版本**：v7.2.0 修复
- **现象**：用户调整"孤立照片时间窗口"和"中间照片时间窗口"参数，匹配结果不变
- **根因**：`find_best_match()` 里直接写了 `max_time_window = 300` 和 `max_time_window = 60`，没有用构造函数传入的 `self.isolated_window` 和 `self.middle_time_window`
- **修复**：改为 `self.middle_time_window` 和 `self.isolated_window`
- **防范**：算法里所有阈值必须引用实例变量，禁止硬编码数字。单测要验证"不同参数产生不同结果"

### Bug-ALG-02：check_photo_time_diff 空指针

- **版本**：v7.2.0 修复
- **现象**：首尾照片处理时 prev/next 为 None，访问 `.datetime` 崩溃
- **根因**：没有对 prev_photo/next_photo 做 None 检查
- **修复**：加了 `if prev_photo and next_photo:` 前置判断
- **防范**：遍历列表时，所有邻居访问都要考虑边界元素（第一个没有前驱，最后一个没有后继）

### Bug-ALG-03：match_tail 参数无效

- **版本**：v7.2.0 修复
- **现象**：`match_tail=False` 时尾部孤立照片仍然被匹配
- **根因**：算法里完全没有检查 `self.match_tail` 的值
- **修复**：添加 `if not self.match_tail: return None` 分支
- **防范**：每个构造参数都必须在逻辑中有对应的消费点。写参数时要自问"这个参数在哪里被用到"

### Bug-ALG-04：没有真正的 GPS 插值

- **版本**：一直存在，未修复
- **现象**：文档说"插值匹配"，代码实际只找最近的 GPS 点
- **根因**：`find_best_match()` 遍历所有 GPS 点取 `min(diff)`，没有做前后 GPS 点之间的线性插值
- **影响**：GPS 轨迹点稀疏时（间隔>1分钟），照片位置精度低
- **建议**：重写时实现真正的线性插值 —— 对中间照片，取前后 GPS 点按时间比例计算经纬度

### Bug-ALG-05：时区转换错误（UTC vs 本地时间戳）

- **版本**：v3.0 时期修复
- **现象**：匹配成功率从 98% 骤降到 65%
- **根因**：GPX 时间用 UTC，照片时间是本地时间，比较时用了 `local_time.timestamp()` 而不是 `utc_time.timestamp()`
- **修复**：统一用 UTC 时间戳做匹配计算，显示时转本地时间
- **防范**：时间比较永远基于同一时区（推荐 UTC），只在展示层做本地化。gpx_parser.py 里 `timestamp` 字段必须用 `utc_time.timestamp()`

### Bug-ALG-06：默认参数过于保守

- **版本**：多次修复
- **现象**：默认孤立窗口=5分钟，中间窗口=60分钟，成功率只有 43%；改为 300秒/3600秒后成功率 80%+
- **根因**：初始参数凭直觉设的，没有用真实数据验证
- **防范**：默认参数必须用真实数据集调优后确定，并记录调优依据

## 2. EXIF / GPS 数据写入

### Bug-EXIF-01：海拔 0 被当成 False

- **版本**：v7.1.0 修复
- **现象**：海平面照片（海拔=0）丢失海拔信息
- **根因**：`gps['alt'] if gps['alt'] else None` —— Python 里 `0` 是 falsy
- **修复**：改为 `gps.get('alt')`，只用 key 存在性判断，不用 truthy 检查
- **防范**：**永远不要用 `if value` 检查数值型数据**，应该用 `if value is not None`

### Bug-EXIF-02：海拔键名不一致

- **版本**：v4.0 时期修复
- **现象**：GPX 解析出的海拔数据在后续处理中丢失
- **根因**：gpx_parser.py 用 `'elevation'` 键名，其他模块用 `'altitude'` 键名
- **修复**：统一为 `'altitude'`
- **防范**：所有模块间的数据结构必须用统一的 TypedDict 或 dataclass 定义，禁止各自起名

### Bug-EXIF-03：海拔精度反复变更

- **版本**：多个版本反复修复
- **现象**：先是用 `*100/100`，后改成 `*10/10` 对齐 Pica meta，再改回 `*100/100`
- **根因**：没有一开始就确定精度标准，反复被外部工具格式牵着走
- **最终方案**：`(int(abs(altitude) * 100), 100)` 表示 0.01m 精度
- **防范**：数据格式在项目初期就定义好，写入文档，后续不动

### Bug-EXIF-04：GPS 版本号错误

- **版本**：v7.1.0 修复
- **现象**：GPS Version ID 写的是 EXIF 2.2 (2,2,0,0)，macOS mdls 验证不通过
- **根因**：参考了过时的文档
- **修复**：改为 EXIF 2.3 标准 `(2,3,0,0)`
- **防范**：标准相关的常量要查最新规范确定，不要靠记忆

## 3. 日志系统

### Bug-LOG-01：键名不一致导致 KeyError

- **版本**：v7.1.0 后修复
- **现象**：日志记录跳过的已有 GPS 照片时 KeyError
- **根因**：desktop_app.py 传 `{'latitude': ..., 'longitude': ...}`，logger.py 期望 `{'lat': ..., 'lon': ...}`
- **修复**：logger.py 改为用 `.get('lat', gps.get('latitude'))` 兼容两种格式
- **防范**：模块间传递的数据结构要用统一类型定义，不要靠字符串键名隐式约定

### Bug-LOG-02：错误日志缺失

- **版本**：v5.0 时期修复
- **现象**：主处理异常只打印到控制台，不写 errors.log
- **修复**：所有 except 块加 `logger.log_error()`
- **防范**：每个 except 块必须有日志记录，code review 时检查

## 4. 桌面应用 (tkinter)

### Bug-UI-01：后台线程访问 tkinter 变量

- **版本**：v7.2.0 修复
- **现象**：潜在竞态条件，后台线程读 `self.mode.get()` 等 tkinter 变量
- **根因**：tkinter 不是线程安全的，后台线程不应直接操作 UI 组件或变量
- **修复**：在主线程把所有参数打包成 dict，传给后台线程
- **防范**：后台线程只接收纯 Python 数据（dict/dataclass），不碰任何 UI 对象。重写时这个模式要保留

### Bug-UI-02：变量未初始化导致 UnboundLocalError

- **版本**：v5.0 时期修复
- **现象**：`failed_details` 变量在 dry 模式下未初始化，后续代码引用报错
- **根因**：`failed_details` 在 overwrite/copy 分支里初始化，但 dry 分支跳过了
- **修复**：在函数入口统一初始化 `failed_details = []`
- **防范**：函数内所有分支都可能用到的变量，必须在分支之前初始化

### Bug-UI-03：资源泄漏 —— Image.open 未关闭

- **版本**：v5.0 时期修复
- **现象**：查看大量照片详情后内存持续增长
- **根因**：`show_photo_details()` 中 `Image.open()` 没有 close
- **修复**：加 finally 块确保 `img.close()`
- **防范**：所有文件/图片操作必须用 try-finally 或 with 语句

### Bug-UI-04：分页边界越界

- **版本**：v5.0 时期修复
- **现象**：输入非法页码导致 IndexError
- **根因**：`display_page()` 没有边界检查
- **修复**：加页码范围校验 + 用户提示
- **防范**：所有用户输入的数值都要做范围校验

### Bug-UI-05：进度条在拷贝模式不更新

- **版本**：v4.0 时期修复
- **现象**：拷贝模式下进度条卡住不动
- **根因**：写入/拷贝阶段没有调用 `update_progress()`
- **修复**：在拷贝循环中加入进度更新
- **防范**：进度反馈要覆盖所有耗时操作，不能只在一两个阶段有

## 5. Web 服务

### Bug-WEB-01：Web 服务用了 V2 匹配器而非 V3

- **版本**：v7.2.0 修复
- **现象**：Web 服务匹配成功率低于桌面应用
- **根因**：`gps_service_v3.py` 导入的是 `gps_matcher_v2` 而非 `gps_matcher_v3`
- **修复**：改 import 为 `from gps_matcher_v3 import GPSMatcherV3`
- **防范**：版本化模块（_v2, _v3）要确保所有入口点使用最新版本。或者不用版本后缀，用配置切换

---

## 6. 函数签名与调用

### Bug-SIG-01：修改函数签名后未更新调用点

- **版本**：v5.0 时期（TD-003）
- **现象**：把 `process_in_background(self)` 改为 `process_in_background(self, params)`，但 Thread 创建处没更新
- **根因**：改了定义，没改调用
- **防范**：改函数签名时，用 IDE 的 Find Usages 确认所有调用点。在重构清单里加一项"检查所有调用点"

### Bug-SIG-02：修复不完整导致新错误

- **版本**：v5.0 时期（TD-004）
- **现象**：修复 TD-003 后，忘了在 `start_processing()` 里构造 `params` 字典
- **根因**：只改了 Thread 调用的参数，没改参数的来源
- **防范**：修复 bug 时要从调用链的起点到终点完整检查，不能只改中间一环

### Bug-SIG-03：params 定义不完整

- **版本**：v5.0 时期修复
- **现象**：`params` 字典缺少 `output_dir`、`keep_structure` 等必需键
- **根因**：最初只传了 gpx_dir 和 photo_dir，后续加功能时忘了补
- **防范**：params 结构用 dataclass 定义，IDE 会提示遗漏的字段

## 7. 数据一致性

### Bug-DATA-01：拷贝模式计数器不匹配

- **版本**：v5.0 时期修复
- **现象**：`write_success_count + copy_only_count + copy_failed_count != total`
- **根因**：某些分支（如 mkdir 失败）里用了 `copy_failed_count` 但没有先初始化
- **修复**：加了防御性检查和计数器校验
- **防范**：计数器变量要在函数入口统一初始化为 0，每条分支只增加不跳过

### Bug-DATA-02：拷贝模式不保证所有照片都输出

- **版本**：v6.0/v7.0 修复
- **现象**：匹配失败的照片没有被拷贝，导致输出目录照片数量少于输入
- **修复**：改为"所有照片都拷贝"（成功的写入 GPS，失败/跳过的原样拷贝）
- **防范**：拷贝模式的契约是"输出数量 == 输入数量"，每条代码路径都必须保证拷贝

## 8. 分类总结：重写时必须注意的模式

| 类别 | 高频 bug 模式 | 防范措施 |
|------|-------------|---------|
| **空指针** | prev/next 为 None，变量未初始化 | 边界检查 + 函数入口统一初始化 |
| **数据格式** | 键名不一致（lat/latitude、elevation/altitude） | 用 TypedDict/dataclass 定义跨模块数据结构 |
| **数值陷阱** | 0 当 False（海拔）、truthy 检查数值 | 用 `is not None` 代替 truthy |
| **线程安全** | 后台线程访问 tkinter 变量 | 参数在主线程打包为纯数据传递 |
| **参数生效** | 构造参数没在逻辑中使用 | 每个参数必须有对应的测试用例验证 |
| **修复完整性** | 改了定义没改调用，改了调用没改来源 | 改动要覆盖完整调用链 |
| **文件资源** | Image.open 不关闭 | 所有资源操作用 context manager |
| **时区** | UTC/local 混用 | 内部统一 UTC，只在展示层本地化 |
| **精度标准** | 海拔精度反复变更 | 项目初期确定标准并写入文档 |
| **日志遗漏** | except 块不记录日志 | 每个 except 必须有日志 |
