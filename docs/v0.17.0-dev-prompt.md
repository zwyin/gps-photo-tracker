## 第一批：BUG-1（跳过照片污染自动跟随 + 计算GPS误显）

**两个现象同根因，一次修复。**

### 根因

1. `src/gps_photo_tracker/core/gps_matcher.py` 第 40-44 行，跳过时设置 `gps=photo.existing_gps`（应为 `None`）
2. `worker.py` 第 148-150 行从 `result.gps` 取值填入计算GPS列 → 跳过照片计算GPS列显示不应有的值
3. `gps_matcher.py` 第 56 行 `_second_pass_neighbor_follow` 的 `succeeded` 列表未排除 `r.method=="skipped"` → 跳过照片被当作有效邻居 → 02447 跟随了 02446（已跳过），拿到 1 小时前的位置

### 修改清单

| # | 文件 | 行号 | 修改 |
|---|------|------|------|
| 1 | `gps_matcher.py` | 43 | `gps=photo.existing_gps` → `gps=None` |
| 2 | `gps_matcher.py` | 56 | succeeded 列表增加 `r.method != "skipped"` |

### 影响

- 修改 1：跳过照片 `result.gps=None` → worker 层 `result.gps.latitude` 为 None → 计算GPS列自动显示"—"
- 修改 1+2：双重保障，跳过照片不再进入 succeeded 列表（即使漏改一处，另一处也能拦截）
- GPS(后) 列不受影响：GUI 层对 skipped 行从 GPS(前) 取值，逻辑独立于 result.gps

### 测试 case

```
输入：
  photo_A: 无GPS, timestamp=10:00 → 第一回合就近匹配成功, gps=25.0,102.0
  photo_B: 有GPS, timestamp=10:02 → 跳过 (method=skipped)
  photo_C: 无GPS, timestamp=10:03 → 第一回合失败

期望：
  photo_B.result.gps == None
  photo_C 第二回合不应跟随 photo_B
  photo_C 第二回合应跟随 photo_A (如果时间差在阈值内)
```

- **相关文件**：`gps_matcher.py`, `worker.py`, `main_window.py`

## 第二批：BUG-2（GPS覆盖率统计回归）

v0.17.0 BUG-1 修复引入的回归，就近修复。

### 现象

GPS覆盖率显示 `43.2% → 50.7%`，期望 `43.2% → 93.8%`。
146 张照片中 63 张 skipped（已有GPS），算法匹配成功 74 张，最终仅 9 张无GPS。
但覆盖率只算了 74/146，漏掉了 63 张 skipped。

### 根因

v0.17.0 将 skipped 照片 `result.gps=None` → worker 层 `latitude=None`。
覆盖率计算用 `latitude is not None` 判断，skipped 被排除。

### 修改

`main_window.py` 第 784-788 行：

```python
# 修复：skipped 照片有 existing_gps，GPS(后) 有值，应计入覆盖率
gps_with_result = sum(
    1 for d in details
    if d.get("method") != "protected"
    and (d.get("latitude") is not None or d.get("method") == "skipped")
)
```

同时检查第 1278 行 `_update_pre_process_summary` 的覆盖率口径。
