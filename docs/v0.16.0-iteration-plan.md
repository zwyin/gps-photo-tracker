## Bug 列表

### BUG-1：跟随方向疑似错误

- **Case**：00975 (14:09:34) 标注"跟随下一个"，但 GPS(后) = 23.6190, 102.8299 = 上一个 00973 的坐标
- **期望**：跟随下一个应该取 00984 的 GPS (23.0873, 102.8166)
- **待确认**：是 Review 逻辑问题还是标签显示问题
- **相关文件**：Review 对话框跟随逻辑, `main_window.py`

### BUG-2：图片预览尺寸仍未修复

- **历史**：v0.11.0 BUG-3、v0.14.0 BUG-3 均声称修复但未生效
- **布局说明**：
  - 右半区分为上下两部分：上=结果列表，下=图片预览，两者等宽
  - 图片预览区域中，预览图宽度 = 预览区宽度的 **1/3 或 1/2**（锁定比例）
  - 预览图高度自动适配（保持宽高比）
  - 拖动分隔线或调整窗口时实时响应
- **相关文件**：`main_window.py`, `photo_preview.py`

### BUG-3：列表方式列缺少下拉选框

- **需求**：结果列表"方式"列应支持下拉选框，允许用户手动选择处理方式
- **可选方式**：跟随上一个、跟随下一个、手动选 GPS、跳过 等
- **逻辑要求**：
  - 选择"跟随上一个"→ 向上查找最近一张有 GPS(后) 的照片，取其坐标
  - 选择"跟随下一个"→ 向下查找最近一张有 GPS(后) 的照片，取其坐标
  - 方向和坐标来源必须与选择一致（参考 BUG-1）
- **联动刷新**：选择方式后，该行其他列需同步更新：
  - GPS(后) 列 → 填入跟随到的坐标
  - 状态列 → 更新为"成功"
  - 备注列 → 记录操作（如"列表选择: 跟随上一个"）
  - 总览统计 → 重新计算成功率
- **当前状态**：列表 `setEditTriggers(NoEditTriggers)`，方式列是纯文本
- **相关文件**：`result_table.py`, `main_window.py`

- **相关文件**：`main_window.py`, 参数配置相关文件

### FEAT-2：匹配算法增加第二回合（邻居跟随）

- **需求**：第一回合匹配失败的照片，自动尝试用已成功邻居的 GPS 做跟随匹配
- **两回合流程**：
  - **第一回合**：现有逻辑（插值 + 就近匹配），标记成功/失败
  - **第二回合**：遍历第一回合失败的照片，查找前后最近的已成功匹配照片，取其 GPS
  - 方式标记为"自动跟随上一个/下一个"
- **时间阈值**：使用 `isolated_window`（默认 300s），邻居照片的拍摄时间差在阈值内才允许跟随
- **Case 详情**：
  ```
  序号  文件名          日期时间              GPS(前)          GPS(后)           方式        状态
  13   DSC00973.JPG   2026-02-09 09:19:08   无               23.6190,102.8299  就近        成功
  14   DSC00975.JPG   2026-02-09 14:09:34   无               23.6190,102.8299  跟随下一个  成功
  15   DSC00976.JPG   2026-02-09 14:11:54   23.6190,102.8299 23.6190,102.8299  已跳过      已跳过
  16   DSC00978.JPG   2026-02-09 14:17:40   无               —                 (空)        无GPS覆盖
  17   DSC00984.JPG   2026-02-09 15:15:27   无               23.0873,102.8166  就近        成功
  18   DSC00987.JPG   2026-02-09 15:15:51   23.0873,102.8166 23.0873,102.8166  已跳过      已跳过
  ```
  - 00975 (14:09) 离 00973 (09:19) 约 4h50m → 第二回合不应跟随
  - 00975 (14:09) 离 00984 (15:15) 约 1h6m → 第二回合不应跟随
  - isolated_window 阈值有效拦截不合理的跟随
- **相关文件**：`gps_matcher.py`, `main_window.py`

### FEAT-3：导出功能增强（格式选择 + 默认文件名）

- **背景**：v0.15.0 已实现基础导出，需增强
- **格式选择**：导出时提供 CSV / Markdown 格式选项
- **默认文件名**：基于输入照片目录名自动生成
  - 拼接规则：`GPS追踪_{照片目录名}_{日期}.{csv|md}`
  - 示例：照片目录为 `0207`，日期为 `2026-02-09` → `GPS追踪_0207_2026-02-09.csv`
  - 特殊字符处理：空格→下划线，中文保留，去除不安全字符（`/\:*?"<>|`）
- **相关文件**：`main_window.py`, `result_table.py`

### FEAT-4：应用图标替换

- **需求**：程序运行时底部任务栏/macOS Dock 显示空白图标，替换为有意义的图标
- **图标内容**：体现"照片+GPS"主题（如相机+定位针）
- **要求**：
  - 找一个合适的开源图标（如 Flaticon / Icons8 等）
  - 提供多尺寸：16x16、32x32、128x128、256x256、512x512
  - 格式：.ico（Windows）+ .icns（macOS）+ .png（通用）
  - 在 `main_window.py` 中通过 `setWindowIcon()` 设置
- **相关文件**：`main_window.py`, 新增图标资源文件

### FEAT-5：列表批量选择修改方式

- **需求**：Shift 批量选中多行后，可统一修改方式（主要针对跟随上一个/下一个）
- **交互**：
  - Shift+点击批量选中多行（已支持）
  - 在方式列选择"跟随上一个"或"跟随下一个"
  - 所有选中行逐一执行跟随逻辑，每行独立查找各自的邻居 GPS
- **每行独立计算**：
  - 跟随上一个：每行各自向上查找最近有 GPS(后) 的行
  - 跟随下一个：每行各自向下查找最近有 GPS(后) 的行
  - 不允许所有选中行取同一个坐标，必须每行独立计算
- **联动刷新**：每行的 GPS(后)、状态、备注、总览统计同步更新
- **数据一致性保障**：
  - 列表中的修改必须传递到后续步骤（COPY/OVERWRITE）
  - 内部数据结构 `_result_details` 同步更新
  - 导出功能导出的是修改后的最终数据
  - 与步骤引导式工作流（v0.14.0 FEAT-1）第三步"执行"的数据流一致
- **相关文件**：`result_table.py`, `main_window.py`
