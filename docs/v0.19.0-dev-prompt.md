## 第一批：BUG-1 + FEAT-1（写入阶段信号重构 + 写入状态列）

这两个强关联，一起实现。BUG-1 的推荐修复方案就是 FEAT-1。

### 根因

预览匹配阶段：Worker 通过 `photo_signal` 逐张 emit → `_on_photo_processed` 向列表 insertRow。
写入阶段（COPY/OVERWRITE）：Worker 的 `write_phase` 也有 `on_photo` 回调，同样 emit `photo_signal`（worker.py 第 279 行）。
`_on_photo_processed` 再次被调用，追加重复行。

关键代码位置：
- worker.py 第 279 行：`self.photo_signal.emit(detail)` — 写入阶段也在 emit
- worker.py 第 282-288 行：`write_phase` 调用时传了 `on_photo=on_photo`
- main_window.py 第 679 行：`_on_photo_processed` — 无条件 insertRow
- main_window.py 第 640-652 行：`_on_step3_execute` 创建新 Worker，没有清空列表

### 实现方案：写入专用信号 + 写入状态列

#### 1. Worker 增加写入专用信号

`worker.py`：
```python
class Worker(QThread):
    photo_signal = Signal(dict)        # 匹配阶段：新增行
    write_signal = Signal(dict)        # 写入阶段：更新已有行（新增）
    done_signal = Signal(dict)
```

写入阶段的 `on_photo` 回调改为 emit `write_signal`（而非 `photo_signal`）：
```python
# worker.py write 执行路径中（约第 279 行）：
# 将 self.photo_signal.emit(detail) 改为 self.write_signal.emit(detail)
```

#### 2. GUI 层连接 write_signal

`main_window.py` 的 `_on_step3_execute` 中：
```python
self._worker.write_signal.connect(self._on_write_update)
```

新增 `_on_write_update(self, result_dict)` 方法：
- 按文件名在已有列表中找到对应行
- 更新该行的"写入状态"列
- 不新增行，不修改其他列

#### 3. 新增"写入状态"列

`result_table.py` 第 59 行，列数从 8 增至 9：
```python
results_table.setColumnCount(9)
results_table.setHorizontalHeaderLabels(
    ["文件名", "日期时间", "GPS(前)", "计算GPS", "GPS(后)", "来源", "状态", "写入状态", "备注"]
)
```

写入状态值：
| 值 | 含义 |
|----|------|
| 空 | 预览阶段，尚未写入 |
| 已复制 | COPY 模式写入成功 |
| 已覆盖 | OVERWRITE 模式写入成功 |
| 跳过 | 跳过的照片（有 GPS 或 protected） |
| 失败 | 写入失败 |
| 已取消 | 用户取消 |

#### 4. 导出也需同步更新

导出功能（`result_table.py` / `main_window.py`）的 CSV 输出需要包含新列。

### 相关文件

- `worker.py`：新增 `write_signal`，写入阶段 emit 改用 write_signal
- `main_window.py`：新增 `_on_write_update`，连接 write_signal，写入状态列填充
- `result_table.py`：增加第 9 列

## 第二批：BUG-2（写入完成弹窗延迟）

### 修复

`main_window.py` 的 `_on_done` 方法（第 1112 行），在弹窗前加状态保护：

```python
def _on_done(self, result_dict: dict):
    self._set_processing(False)
    # ... 现有逻辑 ...

    # 弹窗前检查：如果用户已开始新一轮操作，跳过弹窗
    if not self._has_preview_results() or self._result_details:
        # 正常完成，显示弹窗
        QMessageBox.information(...)
    else:
        # 已开始新任务，仅更新 statusBar
        self.statusBar().showMessage("上一轮写入已完成")
```
