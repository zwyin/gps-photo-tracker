# v0.16.0 开发启动提示词

将以下内容粘贴到新会话中启动开发：

---

## 提示词

```
按 v0.16.0 迭代计划开始开发。先阅读以下文档：
- docs/v0.16.0-iteration-plan.md（3 bug + 5 feature）
- docs/execution-flow-v0.11.0.md（GPS 匹配算法详细流程）

本次共 8 项，按依赖关系分 5 批执行。

## 全局要求

- 每个 bug 必须新增测试 case 覆盖原始场景，防回归
- 测试 case 标注对应 issue 来源

## 第一批：BUG-2（图片预览尺寸，三次未修复）

这个问题连续三个版本声称修复但未生效，务必彻底解决。

规格：
- 右半区上下分栏：上=结果列表，下=图片预览，等宽
- 预览图宽度 = 预览区宽度的 1/3（锁定比例）
- 预览图高度自动适配（保持宽高比）
- 拖动分隔线或调整窗口时实时响应

注意：
- 之前修复可能改了代码但布局约束覆盖了，或者信号没连接
- 必须启动 GUI 实际验证：拖动分隔线、调整窗口大小
- 修复后截图或描述验证结果

## 第二批：BUG-1（跟随方向错误）+ BUG-3（方式下拉选框）

这两个关联：BUG-3 新增下拉选框，跟随逻辑必须正确（参考 BUG-1）。

### BUG-1：跟随方向疑似错误
- 00975 标"跟随下一个"但取了上一个坐标
- 排查 Review 和箭头键的跟随逻辑，确认方向判定正确
- 新增测试 case

### BUG-3：方式列加下拉选框
- 方式列改为 QComboBox，选项：跟随上一个、跟随下一个、跳过 等
- 选择后执行跟随逻辑，该行 GPS(后)、状态、备注、总览同步更新
- 跟随方向逻辑与 BUG-1 修复保持一致
- 需要处理：QTableWidget 的 setCellWidget / setEditTriggers 调整

## 第三批：FEAT-5（批量选择修改方式）

依赖 BUG-3 的下拉选框。

### FEAT-5：批量选中后统一修改方式
- Shift 批量选中多行后，方式列的下拉选框对所有选中行生效
- 每行独立计算跟随坐标（不允许所有行取同一个坐标）
- 每行的 GPS(后)、状态、备注、总览同步更新
- 数据一致性：_result_details 同步更新，传递到 COPY/OVERWRITE

## 第四批：FEAT-2（两回合匹配，核心算法）

### FEAT-2：匹配算法增加第二回合
- 在 gps_matcher.py 中，第一回合完成后，对失败照片做第二回合
- 查找前后最近的已成功匹配照片，时间差 ≤ isolated_window → 跟随
- method 标记 "auto_follow_prev" / "auto_follow_next"
- Case 验证（数据在 docs/v0.16.0-iteration-plan.md）：
  00975 离前后邻居都超 1h → 第二回合应正确拦截
- 新增测试 case

## 第五批：FEAT-1 + FEAT-3 + FEAT-4（UI 增强，可并行）

### FEAT-1：恢复默认参数按钮
- "智能设置"旁加"恢复默认"按钮，恢复 MatcherConfig 默认值

### FEAT-3：导出功能增强
- 格式选择：CSV / Markdown
- 默认文件名：GPS追踪_{照片目录名}_{日期}.{csv|md}
- 特殊字符替换

### FEAT-4：应用图标替换
- 找一个"照片+GPS"主题的开源图标
- 多尺寸：.ico + .icns + .png
- main_window.py 中 setWindowIcon() 设置

## 质量要求

- 每批完成后跑完整测试套件
- BUG-2 必须启动 GUI 实测验证
- BUG-1、FEAT-2 必须新增测试 case
- FEAT-5 完成后验证批量操作 + COPY 执行数据一致性
- 全部完成后跑覆盖率统计
```
