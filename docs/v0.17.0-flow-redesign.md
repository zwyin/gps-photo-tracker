## 一、四步流程定义

```
① 预览匹配 → ② 自动跟随 → ③ 审核修正(可多次) → ④ 执行写入
                                  ↑
                            用户最终决策点
                            之后不再有算法介入
```

**核心原则**：

1. ③ 审核修正是写入前最后一个人为环节
2. ③ 之后直接到 ④，不再回退到 ①②
3. ④ 执行写入 = 所见即所得，表格显示什么就写什么
4. 每个步骤语义清晰，用户可理解、可预期

## 二、各步骤详细定义

### ① 预览匹配

- **输入**：照片目录 + GPX 轨迹文件
- **处理**：对每张照片，找到时间匹配的轨迹段，计算 GPS
- **输出结果**：

| 来源标签 | 含义 |
|---------|------|
| ① 插值 | 照片处于两张轨迹点之间，线性插值计算 GPS |
| ① 就近 | 照片只匹配到一个轨迹点，直接使用该点 GPS |
| — 失败 | 无轨迹覆盖 / 时差过大 / 孤立且禁用 |

- skipped 照片（已有 GPS）不参与匹配，来源=—，状态=已跳过

### ② 自动跟随

- **输入**：① 的输出结果
- **处理**：对 ① 中失败的照片，寻找时间距离最近的已成功照片，在其 isolated_window（默认 300 秒）范围内则跟随
- **约束**：
  - 不跟随 skipped 照片（其 GPS 可能不可靠）
  - 使用动态扫描（非预建列表），支持级联传播
- **输出结果**：

| 来源标签 | 含义 |
|---------|------|
| ② 跟随 | 从邻近成功照片复制 GPS（方向记在备注列） |

- 本步骤只运行一次，不在后续环节重复执行

**① 之后所有照片状态，及 ② 对它们的处理方式**：

| # | 照片条件 | 参数 | ① 结果 | ② 处理 | ② 可否作为来源 |
|---|---------|------|--------|---------|--------------|
| 1 | 有 GPS | overwrite=False | skipped, gps=None, success=True | 跳过（已成功） | ✗ method=skipped |
| 2 | 有 GPS | overwrite=True + 匹配成功 | 插值/就近, gps=新值, success=True | 跳过（已成功） | ✓ 有计算GPS |
| 3 | 有 GPS | overwrite=True + 匹配失败 | 失败, gps=None, success=False | **处理**（寻找来源） | ✗ 无GPS |
| 4 | 无 GPS | 有轨迹覆盖，两点间 | 插值, gps=计算值, success=True | 跳过（已成功） | ✓ 有计算GPS |
| 5 | 无 GPS | 有轨迹覆盖，单侧点 | 就近, gps=计算值, success=True | 跳过（已成功） | ✓ 有计算GPS |
| 6 | 无 GPS | 无轨迹覆盖 | 失败(NO_GPS_COVERAGE), gps=None | **处理**（寻找来源） | ✗ 无GPS |
| 7 | 无 GPS | 轨迹覆盖但时差过大 | 失败(TIME_DIFF), gps=None | **处理**（寻找来源） | ✗ 无GPS |
| 8 | 无 GPS | 孤立 + match_isolated=False | 失败(ISOLATED_DISABLED), gps=None | **处理**（寻找来源） | ✗ 无GPS |
| 9 | 无时间戳 | — | 排除，不进入匹配 | 不处理 | 不可作来源 |

**总结**：
- ② **处理**：#3、#6、#7、#8（① 中失败的照片）
- ② **来源**：#2、#4、#5（① 中匹配成功且有计算 GPS 的照片）
- ② **跳过**：#1（skipped，不可靠）、#9（无时间戳）
- **关键参数**：`isolated_window`（默认 300 秒）决定跟随的最大时差限制

### ③ 审核修正（可多次）

③ 有两个操作入口：

**入口 A：审核对话框**
- 打开审核对话框，批量处理失败照片
- 可选跟随上一个/下一个、手动输入 GPS
- 确认后结果回写到主界面列表

**入口 B：主界面列表行级操作**
- 在列表中选中某一行，直接修改该行的方式
- 可用操作：跟随上一行、跟随下一行、保护/取消保护

**行级操作的联动规则**：

当用户修改某一行的"来源"时，该行其他列自动更新：

| 操作 | GPS(后) | 来源 | 状态 | 备注 |
|------|---------|------|------|------|
| 跟随上一行 | 动态查找上一个可信记录的 GPS(后) | ③ 跟随 | 成功 | 跟随上一行 |
| 跟随下一行 | 动态查找下一个可信记录的 GPS(后) | ③ 跟随 | 成功 | 跟随下一行 |
| 手动输入 | 用户填写的值 | ③ 手动 | 成功 | — |
| 保护 | **冻结当前 GPS(后)** | — | 已保护 | 保存当前状态到行级快照 |
| 取消保护 | 从该行快照恢复 | 从该行快照恢复 | 从该行快照恢复 | 清除该行快照 |

> **关键修正**：保护时 GPS(后) 冻结为**当前值**（而非 GPS(前)）。
> 原因：照片可能没有 GPS(前)，此时"GPS(后)=GPS(前)"会让已计算的 GPS 丢失，
> 与"保护元数据不被修改"的语义矛盾。保护 = 冻结当前所见，不做任何计算。

**可信记录的定义**（"跟随"操作的 GPS 来源）：

| 来源 | 是否可信 | 原因 |
|------|---------|------|
| ① 插值 | ✓ | 算法计算，来自 GPX 轨迹数据 |
| ① 就近 | ✓ | 算法计算，来自 GPX 轨迹数据 |
| ② 跟随 | ✓ | 从可信来源级联 |
| ③ 跟随 | ✓ | 用户确认 |
| ③ 手动 | ✓ | 用户确认 |
| 已保护 | ✗ | 保护 = 冻结不动，不应作为跟随源传播 GPS |
| 已跳过 | ✗ | 现有 GPS 可能不可靠（相机 GPS/人工标注） |
| 失败 | ✗ | 无 GPS |

- "跟随"操作**按时间戳排序**查找最近的可信记录（而非视觉行顺序）
- 只影响当前一行，不影响其他行

**保护机制（`.` toggle）**：

- 按一次 `.` → 保护：保存该行当前完整状态（GPS(后)、来源、状态、备注）到行级快照，然后切换为保护态
- 再按一次 `.` → 取消保护：从该行的快照恢复，不做全局重算
- 每行独立快照，互不干扰
- **已保护的行禁止箭头键跟随操作**（无论 GPS(后) 是否为空）
- 多次保护/取消保护：每次保护时**覆盖**该行快照为当前状态

示例：
```
行1 ①插值 GPS=25.1484 → 保护(快照存①插值 GPS=25.1484) → 已保护 GPS(后)=25.1484
行2 ②跟随 GPS=25.0554 → 保护(快照存②跟随 GPS=25.0554) → 已保护 GPS(后)=25.0554
行3 ①就近 GPS=25.1401 → 保护(快照存①就近 GPS=25.1401) → 已保护 GPS(后)=25.1401

行1 取消保护 → 恢复 ①插值 GPS=25.1484  (行1自己的快照)
行2 取消保护 → 恢复 ②跟随 GPS=25.0554  (行2自己的快照)
行3 仍保护    → 已保护                   (行3的快照还在)
```

### ④ 执行写入

- **输入**：表格当前状态
- **处理**：
  - 有 GPS(后) 且非保护状态的照片：写入 GPS 元数据（COPY 模式拷贝后写入，OVERWRITE 模式直接覆盖）
  - skipped 照片：不修改 GPS 元数据
  - 已保护照片：不修改 GPS 元数据（等同于 skipped）
  - 失败照片：COPY 模式下仅拷贝文件不写 GPS
- **所见即所得**：表格显示什么就写什么，不再重新匹配

## 三、来源列设计（改动前后对比）

**改动前**（"方式"列，9 种值）：

| 旧标签 | 阶段 | 问题 |
|--------|------|------|
| 插值 | 第一回合 | 无阶段标识 |
| 就近 | 第一回合 | 无阶段标识 |
| 自动跟随上一个 | 第二回合 | "自动"与手动易混淆 |

**改动后**（"来源"列，7 种值）：

| 新标签 | 阶段 | 说明 |
|--------|------|------|
| ① 插值 | 预览匹配 | 线性插值 |
| ① 就近 | 预览匹配 | 最近轨迹点 |
| ② 跟随 | 自动跟随 | 邻近照片 GPS |
| ③ 跟随 | 审核修正 | 手动跟随（箭头键 + 审核对话框） |

| — | 无计算 | 已保护（用户锁定） |

**变化总结**：
- 列名"方式" → "来源"，更准确表达"GPS 从哪来"
- ①②③ 前缀标识阶段，一眼看出哪步产生的

- 9 种值 → 7 种值，更简洁
- skipped 来源从"已跳过"改为"—"（无计算）
- 箭头键跟随和审核对话框跟随统一使用"③ 跟随"，通过备注列区分来源

## 五、`.` 保护机制（改动前后对比）

**改动前**：

| 行为 | 说明 |
|------|------|
| 语义 | 恢复到算法原始结果（`_original_details`） |
| 生效条件 | 仅对有 Review 修改的照片有效果 |
| 对未修改照片 | 无效果（恢复到相同状态） |
| 对 ①② 算法结果 | 不影响 |

**改动后**：

| 行为 | 说明 |
|------|------|
| 语义 | **保护这张照片的地理元数据不被修改** |
| 生效条件 | 任何照片都可保护（①②③ 均可） |
| toggle | 按一次保护（保存快照），再按一次取消保护（恢复快照） |
| 优先级 | 最高，高于全局模式（覆盖/不覆盖） |
| 效果 | **冻结当前 GPS(后)**（不是重置为 GPS(前)），来源=—，状态=已保护 |
| 执行时 | 等同 skipped，不修改 GPS 元数据 |
| 快照 | 行级独立，保存保护前完整状态，取消保护时精确恢复 |
| 箭头键 | 已保护状态下箭头键无效（需先取消保护） |

**快照存储**：

```python
# 存储位置：MainWindow 实例变量，独立于 _result_details 和 _original_details
self._protection_snapshots: dict[int, dict] = {}
# key = data_row index, value = {"gps_after": str, "method": str, "status": str, "remark": str,
#                                  "latitude": float|None, "longitude": float|None, "altitude": float|None}
```

- `_original_details` 保留，记录 ①② 步骤的原始算法结果（用于统计和调试）
- `_protection_snapshots` 记录保护前的用户编辑结果（用于取消保护恢复）
- 两者职责不同，互不干扰
- **生命周期**：`_protection_snapshots` 绑定于当前预览会话。新的 ① 预览（`_on_step1_preview`）启动时，必须同时清空 `_protection_snapshots`，避免旧快照索引错位
- **快照不保留历史**：每次保护时覆盖前一次快照。取消保护只恢复到最近一次保护前的状态，不会回退到更早的状态
- **保护无 GPS 的行是合法操作**：`GPS(后)="—"` 的行也可以保护，防止被批量操作误改。取消保护时恢复为失败状态（仍无 GPS）

**与 skipped 的区别**：

| | 已跳过 | 已保护 |
|--|--------|--------|
| 触发 | 自动（照片已有 GPS） | 用户手动按 `.` |
| 语义 | 系统判断 | 用户主动保护 |
| GPS(后) | = GPS(前) | **冻结保护前值** |
| 元数据处理 | 不修改 | 不修改 |
| 可否恢复 | N/A | 再按 `.` 恢复快照 |
| 可否跟随 | 不可作为来源 | 不可作为来源，箭头键无效 |
| 内部 method | `"skipped"` | `"protected"` |

## 六、auto_follow API 分离（改动前后对比）

**改动前**：

```python
class GPSMatcher:
    def match(self, photos, segments):
        # 第一回合
        for photo in sorted_photos:
            results.append(self._match_one(...))
        # 第二回合（私有方法，藏在 match 里面）
        self._second_pass_neighbor_follow(results)
        return results  # ①② 混合结果
```

Worker 调用：`results = matcher.match(photos, segments)` — 一次调用拿 ①② 混合结果。

**改动后**：

```python
class GPSMatcher:
    def match(self, photos, segments):
        """① 预览匹配"""
        for photo in sorted_photos:
            results.append(self._match_one(...))
        return results  # 仅 ① 结果

    def auto_follow(self, results):
        """② 自动跟随（公开方法）"""
        # ... 原 _second_pass_neighbor_follow 逻辑 ...
        return changed_count
```

**调用位置**：在 `GPSTaggingService._run_pipeline` 中分离调用：

```python
# tagging_service.py _run_pipeline 方法内部
match_results = matcher.match(valid_photos, segments)   # ①
changed = matcher.auto_follow(match_results)              # ②
```

Worker 不感知此分离，仍通过 `service.preview()` / `service.process()` 调用。
备注列的 ② 跟随方向信息在 `_on_photo_processed` 中根据 method 值生成。

**行为不变**：①② 仍然串行执行，结果完全一致。仅 API 语义清晰化。

> **关键实现步骤**：从 `match()` 方法中**删除** `self._second_pass_neighbor_follow(results)` 调用。
> 该调用移至新的公开方法 `auto_follow()` 中。否则 ①② 会重复执行。

## 七、跟随操作的可信记录过滤

> **新增**：明确所有跟随操作路径都必须使用可信记录过滤。

当前代码中有 **3 处** 跟随逻辑需要统一应用可信记录过滤：

| 路径 | 代码位置 | 当前状态 | 需要修改 |
|------|---------|---------|---------|
| ② 自动跟随 | `gps_matcher.py` `_second_pass_neighbor_follow` | ✅ 已排除 skipped | 补充排除 protected |
| ③ 审核对话框跟随 | `tagging_service.py` `_apply_follow` | ✗ 未排除 skipped/protected | 需加 `method not in ("skipped", "protected")` |
| ③ 箭头键跟随 | `main_window.py` `_quick_follow_gps` | ✗ 未检查可信记录 | 需加**双向检查**：目标行（被操作行）如果是保护状态则跳过；来源行（候选行）如果不是可信记录则跳过 |
| ③ 审核对话框建议 | `review_dialog.py` `_compute_suggestions` | ✗ 未排除 skipped | 需加排除 |
| ③ 主界面 review 应用 | `main_window.py` `_apply_review_to_table` | ✗ 未排除 skipped | 需加排除 |

**可信记录判断条件**（统一标准）：

```python
def _is_trusted_record(method: str, gps_after_text: str) -> bool:
    """判断该行是否为可信 GPS 来源（用于跟随操作）。"""
    if method in ("skipped", "protected"):
        return False
    if gps_after_text in ("无", "—", ""):
        return False
    return True
```

> **实现备注**：`_apply_follow`（tagging_service）接收的 `ordered` 列表已按时间戳排序，可直接按索引方向搜索。`_quick_follow_gps`（main_window）操作视觉行，需通过 `capture_time_ts` 比较时间戳而非依赖行号顺序。两种方式语义一致，实现方式不同。
